# Review: prd-gate workflow and the PRD/TRD system

Date: 2026-10-07. Scope: the `prd-gate` skill (`kit/.claude/skills/prd-gate/`), the PRD and TRD conventions (`prd-create`, `trd-create`, `docs/templates/`), and their first real instance in `agora-consulta-fe` (`docs/prd/triage-documents/`, `docs/trd/`, `changes/001-qr-document-upload/`).

Goal under review: `prd-gate` is the entry point for every developer, both to implement a new PRD and TRD and to change an existing one. The PRD is always the source of truth: a rule change is discussed with the user (current rule versus proposed rule) until every question is answered, then the PRD is updated, then the TRD, and only then the code.

Verdict: the C5 happy path implements that goal well. The weak points are the side entrances (a new PRD, a decision mid-execution, team work) and the lack of mechanical enforcement: "every question answered" is prose the model can skip. On the docs side, the biggest efficiency wins are mechanical (generated HTML, a freshness check on the TRD) and putting acceptance examples in the PRD so tests come straight from the rule.

Severity: **Critical** breaks the goal; **High** lets a rule change escape discussion or costs a lot per delivery; **Medium** costs time or accuracy regularly; **Low** is polish.

## A. Workflow (prd-gate)

| A01 | Critical | **A new PRD skips the discussion.** A spec from product goes C0, then `/prd-create` M3 (`doc-reader` transcribes it), then back as C2 ("approved rule the code does not meet"), then code. ## B. PRD and TRD efficiency for AI development

| ID | Sev. | Finding | Evidence | Fix |
|---|---|---|---|---|
| B01 | High | **The HTML is a hand-maintained second copy.** One PRD already has a 150 KB `prd.html`; every rule edit is made twice, and G5, G6 and G10 exist only to catch the drift between copies | `agora-consulta-fe/docs/prd/prd.html`; `prd-writing.md` HTML; `repo.md` `html` | Generate it: `scripts/build_prd_html.py` renders the markdown into `docs/templates/prd.html` (same tabs, filters and styling). The gate checks the build is current. The writer stops touching HTML |
| B02 | High | **TRD freshness is not checked.** The gate checks the IDs under "Planned" (G8) and the heading at `--final`; it never checks that the files and symbols the TRD names still exist. T04 ("verified") holds only on the day of creation, and agents trust the map | `gate.py` (only G8, G20 read `docs/trd`); `trd-create` T04 | `gate.py --trd`, in CI: every backticked path under `docs/trd` exists (ERROR); every symbol in "Main symbols" greps in its file (WARNING). A stale map is worse than none |
| B03 | High | **Rules have no examples; expected outcomes live in the TRD.** "Tests to write" holds behavior ("QRF-05: 4 s interval") while the PRD says "every 3 to 5 seconds": the number lives in two places and the TRD restates a rule (T03). The interview's D15 (acceptance) answers have no home in the PRD | `docs/trd/triage.md` Planned; `10-02-facilitator-screen.md` QRF-05 | Optional `Example` per rule in the PRD (input, then expected outcome), required for rules with numbers, branches or failure paths; D15 answers land there. The TRD lists only test file and IDs. The executor writes the failing test straight from the example |
| B04 | High | **"Planned" is heavy and triple-sourced.** The QR change names files, symbols, intervals and header values in the TRD "Planned" section (about 60 lines), again in `design.md`, and again in the 30 KB `plan.md`. Three places to keep aligned; the executor reads only the plan | `docs/trd/triage.md` Planned; `changes/001-qr-document-upload/` | TRD "Planned" holds file, creates or changes, symbols, IDs; no parameters or values. Contracts only in `design.md`. Plan tasks point to the TRD rows by file instead of describing them again |
| B05 | Medium | **Rule status is prose.** `*(approved YYYY-MM-DD, pending code)*` and `*(superseded: ...)*` are text parsed by regex; "what is pending in this area" takes a grep and judgment | `anatomy.md` Markers; `gate.py` G9, G19 | A `Status` column (`proposed`, `approved`, `implemented`, `superseded`). The gate also emits `docs/prd/rules.json` (ID, file, status, Source, Change via, tests, TRD file): one read answers status questions, finds C2 work and feeds the plan |
| B06 | Medium | **Amendments never fold back into the journey.** A change that crosses sections becomes an amendment section (`10-00` to `10-05`) plus notes in the step sections, and Promote keeps it. After a few amendments, reading one step means reading the step, k amendments and the CHANGELOG | `prd-writing.md` "Where to write"; `agent-plan.md` Promote | Promote folds the amendment rows into the step sections that own the behavior (IDs unchanged) or makes the amendment the new step section; INDEX follows |
| B07 | Medium | **Area TRDs grow into monoliths.** `triage.md` is 157 lines and maps only the Documents step ("the other steps are not mapped here"); the full area would be several hundred lines read whole | `docs/trd/triage.md` | TRD files mirror PRD sections inside an area (`docs/trd/triage/documents.md`), with a size limit like the module limit; the gate warns above it |
| B08 | Medium | **The rule-to-file mapping has two unchecked copies.** Module header comments cite PRD IDs (R08) and the TRD "IDs" column cites them too | `SKILL.md` R08; `trd-create` T03 | Keep one (TRD plus tests citing IDs), or have the gate check that the two agree |
| B09 | Medium | **Invariants proved only by review are paid every round.** About ten invariants have "review (gap)" as proof (I-06, I-10, I-11, I-13, I-15, I-36, I-37, I-51); every reviewer agent rechecks them every round, and they still slip | `docs/trd/invariants.md` | Turn the most violated into lint rules or tests (no-console for I-13, import boundaries for I-06, `.env.example` sync for I-10 and I-11), ranked by `gates.sh hotspots`. The ratchet counts the gaps, shrink-only |
| B10 | Medium | **One PRD copied into two repositories with no check.** `triage-documents` is identical today in the frontend and the backend; nothing keeps it so | `agora-consulta-fe/docs/prd`, `modulo-integrador/docs/prd` | One home (the owning repository or meta-docs) referenced at a pinned commit, or `gate.py --sibling` compares hashes of the shared files listed in `repo.md` |
| B11 | Medium | **The cross-repository contract is followed by hand.** "Contracts: none configured"; the frontend follows `design.md` "word for word" | `AGENTS.md` Finding things 5; `docs/trd/triage.md` Planned | Snapshot or generate the frontend types from the backend DTOs (`gates.sh contracts` exists). K08 becomes mechanical and agents stop inferring response shapes |
| B12 | Low | **TRD "History" duplicates `git log`** and grows forever | `docs/templates/trd-feature.md` | Drop it, or keep the last five entries |
| B13 | Low | **Telemetry is not used to slim the docs.** The retro reports cost; it does not show which doc files agents read most or reread | `scripts/gates.sh retro` | Add "most read and most reread doc files" to the retro; those are the first to split or trim |

## C. Consistency fixes

| ID | Finding | Fix |
|---|---|---|
| C01 | Executor ceiling: about 50 tool calls or 30 minutes in `workers.md` and `review.md` V08, but 80 or 45 minutes in the plan header that executors actually read (`agent-plan.md`) | One value, cited from one place |

## Keep

The PRD, TRD, plan, code order with R01; the literal current rule checked by the gate; the "fixing what the PRD documents is C5" trap; questions in product language with a scenario and the recommended option first; the explicit "it is clear" exit; the review ceiling and scoped re-review; one rule per row with permanent IDs; the glossary "Name in code" column; TRD "Known pitfalls", "Must not break" and "Pattern to copy by kind of change"; folder `CLAUDE.md` maps loaded on demand; tests citing IDs with `--trace`; the plan tasks with Owns, Creates and consumes, and Depends on. The eval showed the living-truth flow 27% cheaper than mandatory spec-kit with the same code quality.
