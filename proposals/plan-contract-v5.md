# Implementation contract: agents and context plan

Every interface of `proposals/plan-agents-and-context.md` that more than one agent touches. Cite by ID (I-NN); never ship these IDs in kit files. Paths are repository-relative; `<skill>` is `kit/.claude/skills/prd-flow`.

| ID | Interface |
|---|---|
| I-01 | **Agent definitions** in `kit/.claude/agents/`: `prd-flow-surveyor.md` (model opus, tools Read, Grep, Glob, Bash), `prd-flow-docs.md` (opus; Read, Grep, Glob, Edit, Write, Bash), `prd-flow-executor.md` (sonnet; Read, Grep, Glob, Edit, Write, Bash), `prd-flow-reviewer.md` (sonnet; Read, Grep, Glob, Bash), `prd-flow-recheck.md` (haiku; Read, Grep, Bash). Frontmatter `name`, `description` (one line: when the main dispatches it), `model`, `tools`. The body is the role's briefing (moved from `<skill>/reference/workers/*.md`, which is deleted; `README.md` common rules are folded into each body). `prd-flow-docs` merges writer-prd, writer-trd and planner. Dispatch prompt: `Slug: <slug>. State: <absolute state folder>. Python: <interpreter>. <step or task card>`. Fallback when the agents are not installed: `general-purpose` with "Read `.claude/agents/prd-flow-<role>.md` and follow it" |
| I-02 | **Main card**: the first section of `<skill>/SKILL.md`, at most 25 lines: the allowed and forbidden actions (AG2), the spawn rule (AG9), the agent map pointer, the step-4 formats by reference to I-03, the checkpoint (AG16), no ToolSearch (AG17). SKILL.md at most 6144 bytes |
| I-03 | **Scaffolds by the surveyor**: it writes `state.md`, `pack.md` (with the line `Conflicts: <IDs>` or `Conflicts: none`), `impact.md` (the confrontation), `interview.md` (every dimension row prefilled with its pre-interview state: `doc`, `assumed`, `open`, `n/a`), `approved-rules.md` (rows of every rule to change, current text, marker `*(approved YYYY-MM-DD, pending code)*` placeholder date, plus the `## Conflicts` table) and `changes/NNN-<slug>/decisions.md` from the template. The main only edits states, answers, rule text and resolutions, then runs `gate.py --rules` once |
| I-04 | **Conflict resolution**: `approved-rules.md` has `## Conflicts` with `\| ID \| Resolution \| Note \|`, Resolution one of `rewritten` (the same ID appears as a row under its file heading, new text, marker), `superseded` (listed under `## Supersedes` as `ID: old text`), `compatible` (Note states why). Gate **Q5** in `--rules`: every ID of pack.md `Conflicts:` has a row; `rewritten` has its table row; `superseded` exists in the PRD; `compatible` has a non-empty Note |
| I-05 | **Rewriting a rule keeps its ID** (prd-writing): the rewritten row carries the marker; the old text goes literally to the CHANGELOG at promotion. An ID is never reused for a different rule |
| I-06 | **K14 sweep** (impact.md): a rule stated without condition that the new rule makes false for some input is a conflict and must be rewritten or superseded; the surveyor runs on the strongest model |
| I-07 | **Task card** (agent-plan and the gate): each `### TNN · <result>` has `Contract:` (IDs), `Owns:`, `Read:` (exact paths or `path::symbol`, at most about 25k tokens), `Depends on:`, `Creates / consumes:`, `Tests:`, `Commit:` (message with trailer), `Model:`, `Reviewer:`; at most 25 lines. The last code task owns `docs/trd/<area>.md` for the Planned merge (D4) |
| I-08 | **Waves** (`gate.py --step plan`): prints `WAVE n: T01, T02` per wave (topological, critical path first, at most 4 per wave) and `CRITICAL PATH: T01 > T03`; **P7** error when two tasks of one wave share a file in Owns; **P8** warning when two serial tasks of the same area could be one; **P9** error when a task touches `docs/` or `changes/` without owning it |
| I-09 | **promote.py**: `<python> <skill>/scripts/promote.py <slug> [--dry-run]`. Drops the pending marker of every approved ID; fills Source from the `Source:` lines of `deliveries.md` or the TRD Planned file column; moves superseded and rewritten old text literally into the change's CHANGELOG entry with the `Decisions:` rows of `decisions.md`; rebuilds the HTML when `html_mode` is generated; `git mv changes/NNN-<slug> changes/archive/`; deletes the state folder of the slug except `deliveries.md` until the commit; runs `gate.py --final`; prints at most 10 lines; leaves amendment folds it cannot decide as a listed warning |
| I-10 | **gates.sh close [slug]**: full suite against the baseline, lint, trailers, `gate.py --final`, retro; one block of at most 15 lines, full log in `.claude/prd-flow/state/_close/<slug>.log`; exit 1 on any failure |
| I-11 | **Base resolver**: `origin/<base>`, else local `<base>`, else ERROR with "pass --base"; a missing `--base` ref is an ERROR (never a green run). Implemented in `kit/scripts/kit_config.py` (`resolve_base`) for the kit scripts and mirrored in `gate_core.py` for the gate |
| I-12 | **Budgets**: `repo.md` Gate config `prd_section_budget_lines` (default 200, gate **G31** warning), `trd_budget_lines` (exists), `pack_budget_lines` (exists); `ai-kit.json` `limits.skill_md_bytes` 6144 checked by the ratchet |
| I-13 | **Eval metrics** (`eval/METRICS.md`): `main_calls`, `main_tokens_post_exec`, `main_cache_write` (bust above 30k in one call), `main_only_min`, `first_pass`, `rework_actions`, `max_reruns_per_step`, `conflict_recall`, `dispatch_map` (roles surveyor, docs, executor, reviewer, recheck, by `subagent_type` `prd-flow-<role>` or description), `main_violations`, `review_weighted`, `parallel_factor`, `waves`, `inline_residency`, `ceremony_ratio`, `start_context`, `agents_by_role` |
| I-14 | **Eval arms** (`eval/arms-big.json`): `GATE` (ref `fix/existing-repo-adoption`, protocol `arms/living-gate.md`), `FLOW` (HEAD), `FLOW-FAST` (HEAD, two-phase: phase 1 until the plan is approved and committed, phase 2 a new `claude -p --model sonnet` session that runs `/prd-flow resume <slug>`); scenarios S5 reps 3, S6, S7, S8 reps 1; hermetic environment and pinned `--model` and `--effort` |
| I-15 | **S8**: a small-fixture feature with three tasks, two independent (expected 2 waves), hidden tests, `expected.json` with `expected_waves` |
| I-16 | **Retro KPIs** (`scripts/gates.sh retro`): from `events.jsonl` of a real delivery: main tool calls, agents by role, inline reads before the first surveyor dispatch, gate runs by thread, parallel factor; flagged against the targets of `eval/METRICS.md` |
